# Android platform external blockers

The Android runtime now binds platform entry points through `AndroidPlatformRuntime` and routes Android push deliveries through the worker's FCM transport when the worker is configured.

## FCM

The worker requires all of the following environment variables before it can send through Firebase HTTP v1:

- `OPENTEAM_FCM_PROJECT_ID`
- `OPENTEAM_FCM_CLIENT_EMAIL`
- `OPENTEAM_FCM_PRIVATE_KEY`

The private key must be the service-account PEM, with escaped newlines accepted. Payload construction and the injected transport path are tested without credentials. Until these values are configured, Android push jobs fail with an explicit configuration error and retry according to the existing outbox policy.

## VNC

Android validates the short-lived grant, ticket, origin server, and credential-free WebSocket URL. A production VNC/noVNC transport still needs an Android WebView or noVNC renderer implementation. The current `VncTransport` interface is the integration seam; no bearer token is placed in the socket URL.

## Completed Android entry points

- Browser OAuth starts from the plugin screen, opens the server-provided authorization URL, polls the connection status on return, and exposes cancellation through the authenticated `/api/v0/plugin-connections/:id/authenticate/cancel` contract. The server callback page reports success, cancellation, stale state, or failure.
- The chat composer requests microphone permission, records an M4A voice note, posts it to `/api/v0/transcriptions`, merges the returned transcript into the draft, and preserves a failed recording for retry or discard.
- Cold notification taps preserve the message anchor in the `openteam://chat/...?...message=` deep link, and voice shortcuts open the target conversation before requesting microphone permission.
- Sharesheet file items, including `SEND_MULTIPLE`, are uploaded to `/api/v0/assets` with display names and then sent as validated `AssetRef` metadata. Text-only shares continue to open the selected conversation as draft text.

## Search product fallback

The Android client does not claim an AppSearch provider yet. `AccountScopedSearchFallback` provides deterministic in-memory indexing and query behavior for the currently signed-in account; `SearchIndexRegistry.clear()` is the sign-out boundary. Canonical search remains the authenticated server contract (`GET /api/v0/search`), which keeps ranking and account authorization on the server. A future AppSearch implementation must use an account-specific namespace and clear it on sign-out before replacing this fallback.

## Remaining external blockers

- **FCM credentials:** the worker still needs `OPENTEAM_FCM_PROJECT_ID`, `OPENTEAM_FCM_CLIENT_EMAIL`, and `OPENTEAM_FCM_PRIVATE_KEY` before it can deliver Firebase HTTP v1 notifications.
- **VNC transport:** Android validates grants and constructs a credential-free WebSocket URL, but a production VNC/noVNC renderer still needs an Android WebView or native renderer.
- **Verified App Links:** configure the Gradle property `-PopenteamAppLinkHost=chat.example.com`, publish `docs/android/assetlinks.json.template` with the release signing SHA-256 fingerprint at `https://chat.example.com/.well-known/assetlinks.json`, and run `python3 scripts/android/check-assetlinks.py <assetlinks.json> --host chat.example.com`. The manifest and runtime reject unconfigured or malformed hosts. Arbitrary self-hosted OpenTeam servers cannot share one static verification host, so a real HTTPS host and matching assetlinks file remain deployment requirements.

The Android VNC renderer seam now owns WebView hardening, same-origin navigation, lifecycle attach/detach, clipboard/input bridge contracts, reconnect/error states, and grant validation. The noVNC HTML/JavaScript bundle must still be supplied at `assets/openteam-vnc/index.html`; it is intentionally external to this checkout.
